# Stations — P4 HTTP composition, paired-device runtime and first job

Default-off HTTP composition now joins the durable P1–P3 core. `Stations:Http:Enabled` explicitly enables the API module and separately selects Stations persistence in the migrations host; Worker composition is unchanged. The solution includes Stations.Api. PostgreSQL is the only supported provider and registration/store access rejects other providers.

P4 provides primary-bearer management and exact-own linked PIN setup, same-origin HTTPS opaque-cookie runtime, CSRF protection, minimized current/roster/arrivals reads, attributed reservation check-in, explicit lock/switch/foreground activity and private supervised station-only setup. The original manager session must be inactive before runtime leaves guest-free HandoffPending. Changed-actor check-in recovery is a guest-free read of the exact persisted receipt/provenance; it never retries a mutation as a new actor. Configuration, local checks and synthetic MFA assertions do not establish real MFA enrollment, browser/operator acceptance or production activation. See [Shared-station PIN admission](../../../../docs/operations/stations-production-admission.md) for the remaining deployment, data-lifecycle and operational gates.

The local store methods have a Core suffix deliberately. P2A explicitly registers StationRuntimeService/IStationSessionReader and StationAdmissionCoordinator only when AddStationsRuntime is called. The service checks current Staff/Property/common organization/workspace/fence facts, linked Auth/Access prerequisites, or station-only exact local check-in grant. P4 composes primary AAL2/manager/private setup transport and named, bounded HTTP rate policies; the core remains the authority owner. No returned state is an Auth principal or reusable permission. Configured property processing status is observed for change, not treated as legal processing admission: P3 adapters enforce the existing Reservations operational visibility and write-country gates before arrivals, guest data or check-in, not substitute the property policy activation/lifecycle service. An active staff session alone never authorizes those operations.

One canonical unpadded base64url string encodes32random bytes. Malformed/alternate representations are rejected before lookup. The Stations owner hashes decoded bytes and performs one bounded no-tracking exact-digest unscoped projection of tenant/device coordinates. The globally unique index prevents cross-tenant ambiguity. A fresh child DI scope is then set only from those server coordinates and re-reads the device with normal filters, lifecycle/revocation/expiry/epoch checks before any owner read or action. No client tenant or general scope runner exists, and the ambient scope is unchanged.

Credentials and one-use setup grants pin a closed enrollment authority kind and exact linked subject (or station-only null subject). Unknown/null upgrade rows are retained but fail closed in runtime. Current Staff must match the enrollment origin before KDF, actor lock, counters or setup consumption/replacement. Linked-to-unlinked, station-only-to-linked and linked A-to-B changes require new enrollment; no fallback applies the new account's privileges to an old PIN. This is current-state matching, not historical ABA detection or a cross-owner atomic revision guarantee. Stronger history/activation assurances remain an admission gate. Revoke clears verifier and enrollment subject/kind.

P2B AddStationsManagement requires the real destructive-operation assurance requirement and configured Auth scope. Principal observations bracket the actual Auth session/account and Access/common owner facts. Application services do not authenticate the supplied primary transport. Local property management may pair/re-pair/revoke devices, register/unregister staff, and manage the exact station-only check-in grant. Every manager-issued tenant-wide PIN setup/reset, including initial station-only enrollment, requires tenant-root stations.manage plus recent AAL2; a property grant cannot install the global credential. P4 registers the scoped-descendant stations.manage descriptor with global grants disabled. Workspace permission catalogues and version-six seeds expose it to managers and exclude company-support defaults; existing customized profile authority is not silently expanded. Real-host tests exercise this composition, while core fixtures may register synthetic permissions.

Linked own PIN is device-independent: exact own primary identity/current session/recent AAL2 plus current Staff/common/property and active property registration, without stations.manage or reservations.check-in. SetOwnPin creates/replaces only the own tenant credential, atomically locks that Staff's actors across properties and cancels pending setup. Pairings, registrations, separate grants, other Staff and histories remain intact. Own status exposes only PIN state/revision. The unpublished cookie-dependent linked setup issuance/redemption surface was removed; old linked setup history remains preserved, not converted into authority.

The internal RedeemSeededSetupAsync seam now redeems a manager-issued, short-lived, same-device station-only grant. Target and issuer authority are reobserved after KDF; intentional manager primary sign-out does not invalidate the grant, while current account/authority loss does. P4 exposes the private transport after the persisted original-manager-session handoff prerequisite; local tests are not hosted handoff evidence. An operation ID names one attempt, not PIN digits or randomized verifier bytes. Exact authorized replay resolves the prior outcome before KDF without another replacement/lock/cancellation; a fresh same-member recovery session may recover it without substituting the original stored issuer SessionId. Register/Pair rediscloses no opaque secret on replay: resolve original coordinates, then explicitly re-pair if delivery was lost. New/corrected intent requires a new operation ID. Current-owner comparison is non-atomic and cannot establish continuous authority or ABA history.

Property registration is durable roster membership, not action permission. Registering linked staff does not require check-in permission; ordinary runtime admission still does. Unregister invalidates local actors/pending setup without revoking the tenant PIN or another property's registrations/grants/actors. Active registration is capped at 200 under the tenant lock; inactive history releases capacity and retains its stable roster reference. The locked staff selection resolves exact owner labels only, searches the complete bounded active set before pagination, and discloses no contacts/Auth IDs or denial reasons. Staff labels have positive owner catalogue bindings. A final exact-device re-read rejects names after observed re-pair/revocation/change; it is still a bounded observation, not an atomic cross-owner read or evidence that Switch's explicit Lock completed. Manager station lists include active and revoked history through validated pages (default25/max50) with HasMore, not silent truncation or an invented station-count cap.

One opaque browser credential digest preserves pairing across actor Lock; reset/revoke invalidate active actors. P4 adds opaque Secure/HttpOnly/SameSite=Strict host-only runtime cookies, CSRF and mixed-credential rejection, minimized actor-bound responses and HTTP setup. It does not compose the earlier station bearer-token experiment. A successful unlock receipt replay cannot revive a session whose actor generation or expiry changed. An operation ID names one PIN attempt: its replay returns that original attempt, not another verification. PIN digits are deliberately not stored in its fingerprint.

Unlock alone is not proof of a completed operator switch. The Switch staff journey must scrub locally, submit and resolve its explicit same-operation Lock before attempting the next actor. Owner-Unavailable or enrollment mismatch returns without a core mutation; it must not silently lock on an unavailable observation, nor let the UI auto-restore A. KDF Unavailable retains the P1 guest-free lock outcome and requires explicit state/operation recovery, not automatic PIN retry. Late Lock or other stale mutation responses cannot carry a newer actor's identity.

Counters and rejected-attempt receipts commit together. Credential and independent device budgets are persisted. P1 serializes local Stations mutation transactions per tenant, using the existing shared tenant-termination lock plus a Stations-specific exclusive lock. KDF concurrency is bounded with no local KDF queue. This coarse serialization prioritizes correctness; measured local timing is not multi-instance throughput evidence.

Native PBKDF2-HMAC-SHA256 600,000 iterations, 16-byte random salt, 32-byte output, followed by versioned HMAC pepper from an injected non-database owner. There is no fallback pepper, plaintext PIN export, logging of credentials, or FIPS claim. Domain JSON hides verifier material. Deployment key custody/rotation, workload admission, deployed HTTPS/edge verification and external restore epoch enforcement remain admission gates.

Governed retention, Staff-subject rights and tenant export/destroy owner registration remain deferred admission work. P4 adds explicit default-off migrations-host composition, not target-specific migration approval. The P1 tenant lifecycle row/lock is a persisted prerequisite, not a functioning termination owner. No security/audit retention duration is invented. Restoring a database can restore revoked data; external epoch and credential invalidation must be proven during later operational admission.

Tests use uniquely owned disposable PostgreSQL with actual migrations. No existing database/preview data is touched; no SQL Server history is invented.

The additive migrations are not safe live downgrade promises. P2 Down removes enrollment bindings and restores a constraint rejecting ForegroundActivity(kind8); P2B Down removes registrations/issuer/recovery coordinates and restores a constraint rejecting kinds9–15. Never delete receipts to make Down succeed or allow old code to regain authority from removed bindings. Legacy rows/actors/counters/grants/receipts survive upgrade, with no inferred registrations/issuer/session authority. New OwnPin receipts require original Self/session/property/Staff/revision coordinates in both domain and PostgreSQL constraints. Later operational rollback requires a forward fix or separately verified backup/restore plus external station epoch invalidation and re-enrollment; that procedure is not implemented or admitted here.


Actor idle renewal is now a distinct persisted ForegroundActivity operation with an exact actor/generation receipt and fresh owner admission, capped by absolute/pairing expiry. Exact replay never renews twice. Snapshot/background reads never invoke it. The web may coalesce deliberate visible navigation/activity, not polling or every mouse movement. Actor expiry locks the actor but permits a fresh deliberate PIN if pairing/enrollment remain valid. LastObservedAtUtc is a monotonic state-change/attempt high-water mark, not an activity timestamp: only activation and explicit foreground activity set idle expiry. The transaction lock reserves exclusive access to the device budget before KDF work; failed authentication and rejected unknown/revoked identity or invalid/missing/revoked local authority consume the device budget. Success/stale/Busy/Unavailable do not increment it or erase earlier device failures. Enrollment mismatch is a state change without a PIN failure. Repeated valid switching therefore does not exhaust the device budget. PIN-attempt replay returns the original recorded outcome, not proof of a freshly entered PIN; lock/reset/expiry/generation change makes an old successful unlock replay conflict. P4 supplies minimized typed HTTP failures and endpoint rate limits. Bounded dummy verification, minimized roster timing and deployed abuse/side-channel qualification remain separate gates; neither the core nor the HTTP composition claims constant-time or no-oracle behavior.
