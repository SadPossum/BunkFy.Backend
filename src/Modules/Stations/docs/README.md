# Stations — P1 durable core and P2A paired-device runtime

Default-off, not composed in API/Worker/Migrations hosts or the solution. No endpoint, authentication validator, manager service, roster, arrivals read or check-in adapter is provided by this checkpoint. PostgreSQL is the only supported provider and registration/store access rejects other providers.

The local store methods have a Core suffix deliberately. P2A explicitly registers StationRuntimeService/IStationSessionReader and StationAdmissionCoordinator only when AddStationsRuntime is called. The service checks current Staff/Property/common organization/workspace/fence facts, linked Auth/Access prerequisites, or station-only exact local check-in grant. Primary AAL2/manager/private setup transport and rate-limited HTTP lanes remain later work. No returned state is an Auth principal or reusable permission. Configured property processing status is observed for change, not treated as legal processing admission: P3 must enforce the existing Reservations operational visibility and write-country gates before arrivals, guest data or check-in, not substitute the property policy activation/lifecycle service. An active staff session alone never authorizes those operations.

One canonical unpadded base64url string encodes32random bytes. Malformed/alternate representations are rejected before lookup. The Stations owner hashes decoded bytes and performs one bounded no-tracking exact-digest unscoped projection of tenant/device coordinates. The globally unique index prevents cross-tenant ambiguity. A fresh child DI scope is then set only from those server coordinates and re-reads the device with normal filters, lifecycle/revocation/expiry/epoch checks before any owner read or action. No client tenant or general scope runner exists, and the ambient scope is unchanged.

Credentials and one-use setup grants pin a closed enrollment authority kind and exact linked subject (or station-only null subject). Unknown/null upgrade rows are retained but fail closed in runtime. Current Staff must match the enrollment origin before KDF, actor lock, counters or setup consumption/replacement. Linked-to-unlinked, station-only-to-linked and linked A-to-B changes require new enrollment; no fallback applies the new account's privileges to an old PIN. This is current-state matching, not historical ABA detection or a cross-owner atomic revision guarantee. Stronger history/activation assurances remain an admission gate. Revoke clears verifier and enrollment subject/kind.

The internal RedeemSeededSetupAsync seam validates an already-seeded grant through those same current owner facts; it does not issue grants or implement management/primary-auth setup. An operation ID names one redemption attempt, not PIN digits or randomized verifier bytes. An exact retry resolves the recorded result without deriving/replacing again, only while current pinned origin and installed revision still match. New/corrected intent requires a new operation ID; an uncertain write must first resolve its original operation rather than automatically retrying a PIN.

One opaque browser credential digest preserves pairing across actor Lock; reset/revoke invalidate active actors. Runtime transport, cookie/CSRF, actor-bound responses and HTTP setup are not implemented. A successful unlock receipt replay cannot revive a session whose actor generation or expiry changed. An operation ID names one PIN attempt: its replay returns that original attempt, not another verification. PIN digits are deliberately not stored in its fingerprint.

Unlock alone is not proof of a completed operator switch. The future Switch staff journey must scrub locally, submit and resolve its explicit same-operation Lock before attempting the next actor. Owner-Unavailable or enrollment mismatch returns without a core mutation; it must not silently lock on an unavailable observation, nor let the UI auto-restore A. KDF Unavailable retains the P1 guest-free lock outcome and requires explicit state/operation recovery, not automatic PIN retry. Late Lock or other stale mutation responses cannot carry a newer actor's identity.

Counters and rejected-attempt receipts commit together. Credential and independent device budgets are persisted. P1 serializes local Stations mutation transactions per tenant, using the existing shared tenant-termination lock plus a Stations-specific exclusive lock. KDF concurrency is bounded with no local KDF queue. This coarse serialization prioritizes correctness; measured local timing is not multi-instance throughput evidence.

Native PBKDF2-HMAC-SHA256 600,000 iterations, 16-byte random salt, 32-byte output, followed by versioned HMAC pepper from an injected non-database owner. There is no fallback pepper, plaintext PIN export, logging of credentials, or FIPS claim. Domain JSON hides verifier material. Deployment key custody/rotation, workload admission, online transport and external restore epoch enforcement are later admission gates.

Governed retention, Staff-subject rights, tenant export/destroy owner registration and migrations-host composition are P5. The P1 tenant lifecycle row/lock is a persisted prerequisite, not a functioning termination owner. No security/audit retention duration is invented. Restoring a database can restore revoked data; external epoch and credential invalidation must be proven during later operational admission.

Tests use uniquely owned disposable PostgreSQL with actual migrations. No existing database/preview data is touched; no SQL Server history is invented.

The additive P2 migration is not a safe live downgrade promise. Its generated Down removes enrollment bindings and restores the old receipt constraint, which rejects existing ForegroundActivity(kind8) receipts. Never delete receipts to make Down succeed or allow P1 code to regain authority from removed bindings. Later operational rollback requires a forward fix or separately verified backup/restore plus external station epoch invalidation and re-enrollment; that procedure is not implemented or admitted here.


Actor idle renewal is now a distinct persisted ForegroundActivity operation with an exact actor/generation receipt and fresh owner admission, capped by absolute/pairing expiry. Exact replay never renews twice. Snapshot/background reads never invoke it. The future web may coalesce deliberate visible navigation/activity, not polling or every mouse movement. Actor expiry locks the actor but permits a fresh deliberate PIN if pairing/enrollment remain valid. LastObservedAtUtc is a monotonic state-change/attempt high-water mark, not an activity timestamp: only activation and explicit foreground activity set idle expiry. The transaction lock reserves exclusive access to the device budget before KDF work; failed authentication and rejected unknown/revoked identity or invalid/missing/revoked local authority consume the device budget. Success/stale/Busy/Unavailable do not increment it or erase earlier device failures. Enrollment mismatch is a state change without a PIN failure. Repeated valid switching therefore does not exhaust the device budget. PIN-attempt replay returns the original recorded outcome, not proof of a freshly entered PIN; lock/reset/expiry/generation change makes an old successful unlock replay conflict. Uniform HTTP copy/status, endpoint rate limiting, bounded dummy verification and minimized roster timing remain later gates, not a completed no-oracle/constant-time claim from this core.
